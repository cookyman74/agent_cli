## 2. 핵심 아키텍처 차이: write_todos vs Task\* 도구

### 2.1 현재 write_todos 모델 (전체 교체)

```
LLM → write_todos({ todos: [전체 리스트] }) → 기존 리스트 교체
```

**문제점**:

- 매번 전체 리스트를 보내야 함 → 토큰 낭비
- 개별 태스크 ID 없음 → 의존성 관리 불가
- 소유자(owner) 개념 없음 → SubAgent 위임 불가
- 메타데이터 없음 → 확장성 제한
- 상태: `pending | in_progress | completed | cancelled` (4개)

### 2.2 Claude Code Task\* 모델 (증분 CRUD)

```
LLM → TaskCreate({ subject, description }) → { id: "1" }
LLM → TaskUpdate({ taskId: "1", status: "in_progress" })
LLM → TaskGet({ taskId: "1" }) → 상세 정보
LLM → TaskList() → 전체 요약
```

**장점**:

- 개별 태스크 CRUD → 토큰 효율 (변경분만 전송)
- 자동 증가 ID → 참조 용이
- 의존성 그래프: `blocks` / `blockedBy` → 순서 보장
- `owner` 필드 → SubAgent 위임 가능
- `activeForm` → 진행 중 스피너 표시
- `metadata` → 임의 확장 데이터

### Step 1: TaskStore — 인메모리 태스크 저장소

**새 파일**: `packages/core/src/tools/task-store.ts` **테스트**:
`packages/core/src/tools/task-store.test.ts`

#### 인터페이스 설계

```typescript
// --- 타입 정의 ---

export type TaskStatus = 'pending' | 'in_progress' | 'completed';

export interface Task {
  id: string; // 자동 증가 ("1", "2", ...)
  subject: string; // 명령형 제목 ("Run tests")
  description: string; // 상세 설명
  status: TaskStatus;
  activeForm?: string; // 진행 중 표시 ("Running tests")
  owner?: string; // SubAgent 위임용
  metadata?: Record<string, unknown>; // 확장 데이터
  blocks: string[]; // 이 태스크가 차단하는 태스크 ID 목록
  blockedBy: string[]; // 이 태스크를 차단하는 태스크 ID 목록
  createdAt: number; // timestamp
  updatedAt: number; // timestamp
}

export interface TaskSummary {
  id: string;
  subject: string;
  status: TaskStatus;
  owner?: string;
  blockedBy: string[]; // 미완료된 것만 필터
}

// --- TaskStore 클래스 ---

export class TaskStore {
  private tasks: Map<string, Task> = new Map();
  private nextId: number = 1;

  // CRUD
  create(params: TaskCreateParams): Task;
  get(id: string): Task | null;
  update(id: string, params: TaskUpdateParams): Task | null;
  list(): TaskSummary[];
  delete(id: string): boolean;

  // 의존성 관리
  addBlocks(taskId: string, blockedIds: string[]): void;
  addBlockedBy(taskId: string, blockingIds: string[]): void;
  getOpenBlockers(taskId: string): string[]; // blockedBy 중 미완료만

  // 상태 검증
  private validateStatusTransition(from: TaskStatus, to: TaskStatus): boolean;
}
```

#### 핵심 로직

```typescript
// 생성 시 기본값
create(params: TaskCreateParams): Task {
  const task: Task = {
    id: String(this.nextId++),
    subject: params.subject,
    description: params.description,
    status: 'pending',
    activeForm: params.activeForm,
    metadata: params.metadata,
    blocks: [],
    blockedBy: [],
    createdAt: Date.now(),
    updatedAt: Date.now(),
  };
  this.tasks.set(task.id, task);
  return task;
}

// 상태 전이 규칙
// pending → in_progress → completed
// 어느 상태에서든 → deleted (물리 삭제)
private validateStatusTransition(from: TaskStatus, to: TaskStatus): boolean {
  const VALID_TRANSITIONS: Record<TaskStatus, TaskStatus[]> = {
    pending: ['in_progress', 'completed'],
    in_progress: ['pending', 'completed'],
    completed: [],  // completed는 변경 불가
  };
  return VALID_TRANSITIONS[from].includes(to);
}

// list() 시 blockedBy 필터링 (미완료된 것만)
list(): TaskSummary[] {
  return Array.from(this.tasks.values()).map(task => ({
    id: task.id,
    subject: task.subject,
    status: task.status,
    owner: task.owner,
    blockedBy: this.getOpenBlockers(task.id),
  }));
}
```

#### 설계 결정

| 결정             | 선택                       | 이유                               |
| ---------------- | -------------------------- | ---------------------------------- |
| 저장 방식        | 인메모리 (Map)             | 세션 수명과 동일, 영속화 불필요    |
| ID 형식          | 문자열 자동증가 ("1", "2") | Claude Code 호환, LLM 참조 용이    |
| completed 재변경 | 금지                       | Claude Code 동작과 일치, 실수 방지 |
| deleted 처리     | 물리 삭제                  | ID 재사용 없음, 참조 정합성 유지   |
| blockedBy 표시   | 미완료만 필터              | LLM에 actionable 정보만 제공       |

export interface TaskGetParams {
  taskId: string; // 필수

class TaskGetInvocation extends BaseToolInvocation<TaskGetParams, ToolResult> {
  async execute(): Promise<ToolResult> {
    const task = this.taskStore.get(this.params.taskId);
    if (!task) {
      return {
        llmContent: `Task ${this.params.taskId} not found.`,
        returnDisplay: `Task ${this.params.taskId} not found.`,
        error: {
          message: 'Task not found',
          type: ToolErrorType.INVALID_TOOL_PARAMS,
        },
      };
    }
    return {
      llmContent: JSON.stringify(task),
      returnDisplay: formatTaskDetail(task),
    };
  }
}

#### 2.3 TaskUpdate Tool

**새 파일**: `packages/core/src/tools/task-update.ts`

```typescript
export interface TaskUpdateParams {
  taskId: string; // 필수
  status?: TaskStatus | 'deleted';
  subject?: string;
  description?: string;
  activeForm?: string;
  owner?: string;
  metadata?: Record<string, unknown>;
  addBlocks?: string[]; // 이 태스크가 차단하는 태스크 추가
  addBlockedBy?: string[]; // 이 태스크를 차단하는 태스크 추가
}

class TaskUpdateInvocation extends BaseToolInvocation<
  TaskUpdateParams,
  ToolResult
> {
  async execute(): Promise<ToolResult> {
    const { taskId, status, ...updates } = this.params;

    if (status === 'deleted') {
      const deleted = this.taskStore.delete(taskId);
      if (!deleted) {
        return {
          /* task not found error */
        };
      }
      return {
        llmContent: `Task ${taskId} deleted.`,
        returnDisplay: { todos: this.taskStore.toTodoList() },
      };
    }

    const task = this.taskStore.update(taskId, { status, ...updates });
    if (!task) {
      return {
        /* task not found or invalid transition error */
      };
    }

    return {
      llmContent: JSON.stringify({
        taskId: task.id,
        status: task.status,
        subject: task.subject,
      }),
      returnDisplay: { todos: this.taskStore.toTodoList() },
    };
  }
}
```

#### 공통 패턴

모든 Task\* 도구는:

- `Kind.Other` 카테고리
- 확인(confirmation) 불필요 (`shouldConfirmExecute → false`)
- `returnDisplay`로 `{ todos: Todo[] }` 반환 → 기존 TodoTray UI 재사용
- `llmContent`로 JSON 반환 → LLM이 구조적으로 파싱 가능
- `TaskStore` 인스턴스를 DI로 주입받음

#### 3.3 write_todos 호환 전략

**단계적 마이그레이션**:

1. **Phase A (이번 구현)**: Task\* 도구와 write_todos 공존
   - `write_todos`는 기존 그대로 유지
   - Task\* 도구는 독립적인 `TaskStore` 사용
   - LLM 프롬프트에서 Task\* 도구 우선 사용 권장

2. **Phase B (추후)**: write_todos → TaskStore 연동
   - `WriteTodosTool.execute()`가 내부적으로 `TaskStore`에 동기화
   - `returnDisplay`를 통해 UI 자동 통합

3. **Phase C (추후)**: write_todos 제거
   - `WRITE_TODOS_TOOL_NAME` deprecated
   - LLM 프롬프트에서 완전 제거

**이유**: 기존 Gemini 모델이 `write_todos`를 호출하는 패턴이 학습되어 있으므로,
급격한 제거는 호환성 위험. 점진적 전환이 안전.

### Step 4: TaskStore → TodoList 변환 (UI 통합)

#### 4.1 TaskStore.toTodoList() 메서드

```typescript
// task-store.ts에 추가
toTodoList(): Todo[] {
  const statusMap: Record<TaskStatus, Todo['status']> = {
    pending: 'pending',
    in_progress: 'in_progress',
    completed: 'completed',
  };

  return Array.from(this.tasks.values()).map(task => ({
    description: task.activeForm && task.status === 'in_progress'
      ? `${task.subject} — ${task.activeForm}`
      : task.subject,
    status: statusMap[task.status],
  }));
}
```

**핵심 설계**: `returnDisplay: { todos: Todo[] }` 반환 → 기존 `TodoTray`
컴포넌트가 **수정 없이** 렌더링.

#### 4.2 CLI TodoTray 확장 (선택)

기존 `TodoTray`는 `write_todos` 결과에서 마지막 TodoList를 찾아 표시. Task\*
도구도 동일한 `{ todos: Todo[] }` 포맷을 반환하므로 **추가 수정 불필요**.

추후 고도화 시 확장 가능한 항목:

- 진행률 바 (completed/total)
- `activeForm` 스피너 표시
- 의존성 시각화 (blocked 표시)
- `ctrl+t` 토글 시 상세 뷰 (ID, owner, blockedBy 표시)

##### B. annotations 지원 (선택적)

Claude Code의 `annotations`는 사용자가 선택한 옵션에 대한 메모(notes)를 추가하는
기능. 현재 `ask_user`의 `AskUserResponse`에는 `answers: { [index]: string }`
형태만 존재.

**추가 필요**:

```typescript
export interface AskUserResponse {
  type: MessageBusType.ASK_USER_RESPONSE;
  correlationId: string;
  answers: { [questionIndex: string]: string };
  annotations?: {
    [questionIndex: string]: { notes?: string; markdown?: string };
  }; // 추가
}
```

**우선순위**: P2 (markdown preview보다 낮음, 실제 사용 빈도 낮을 것으로 예상)
