## 1. 패키지 구조

```
gemini-cli/
├── packages/
│   ├── cli/          # 터미널 UI (React/Ink)
│   ├── core/         # 백엔드 로직 엔진
│   ├── a2a-server/   # Agent-to-Agent HTTP 서버
│   ├── test-utils/   # 테스트 헬퍼
│   └── vscode-ide-companion/  # VS Code 확장
├── integration-tests/ # E2E 통합 테스트
├── evals/            # 모델 평가 테스트
├── scripts/          # 빌드/릴리스/유틸 스크립트
├── bundle/           # esbuild 번들 결과물 (배포용)
├── Dockerfile        # 샌드박스 컨테이너 이미지
└── docs/             # 문서
```

### 패키지 의존 관계

```
packages/cli ──────────────→ packages/core
packages/a2a-server ───────→ packages/core
packages/test-utils ───────→ packages/core
integration-tests ─────────→ packages/core (직접 import)
scripts/ ──────────────────→ packages/core (일부 스크립트)
```

## 2. 각 패키지 역할

### `packages/cli` — 터미널 UI 레이어

| 항목   | 내용                                                      |
| ------ | --------------------------------------------------------- |
| 기술   | React + Ink (터미널용 React 프레임워크)                   |
| 엔트리 | `src/gemini.tsx` → `AppContainer`                         |
| 역할   | 사용자 입력 파싱, 터미널 렌더링, 설정 UI, 인증 다이얼로그 |
| bin    | `didim` → `dist/index.js`                                 |

**주요 디렉토리**:

- `src/ui/` — React 컴포넌트, 화면 렌더링
- `src/config/` — 설정 로딩, 확장 관리
- `src/utils/` — 설치 정보, 자동 업데이트, **샌드박스 오케스트레이션**
- `src/core/` — core 패키지 초기화 (`initializer.ts`)

### `packages/core` — 백엔드 로직 엔진

| 항목 | 내용                                              |
| ---- | ------------------------------------------------- |
| 기술 | TypeScript, LLM SDK들                             |
| 역할 | LLM API 호출, 도구 실행, 프롬프트 구성, 정책 엔진 |
| SDK  | `@google/genai`, `@anthropic-ai/sdk`, `openai`    |

**주요 디렉토리**:

- `src/providers/` — **멀티 LLM 어댑터** (Gemini, Claude, OpenAI)
- `src/core/` — 콘텐츠 생성, 클라이언트, 토큰 관리
- `src/tools/` — 내장 도구 (shell, file read/write, grep, glob, web-fetch, MCP)
- `src/services/` — 셸 실행 서비스, 파일 탐색, 채팅 기록
- `src/scheduler/` — 도구 스케줄링, 실행 오케스트레이션
- `src/mcp/` — Model Context Protocol 클라이언트
- `src/policy/` — 도구 승인/안전 정책
- `src/agents/` — 에이전트 시스템
- `src/telemetry/` — 관측성, 로깅

### `packages/a2a-server` — Agent-to-Agent 서버

| 항목 | 내용                                  |
| ---- | ------------------------------------- |
| 기술 | Express.js                            |
| 역할 | 외부 에이전트가 CLI를 HTTP API로 호출 |
| 포트 | `CODER_AGENT_PORT` (기본 41242)       |

core와 동일한 백엔드를 사용하되, 터미널 UI 대신 HTTP 엔드포인트로 노출.

### `packages/test-utils` — 테스트 유틸리티

비공개(private) 패키지. PTY 관리, 테스트 픽스처 등 통합 테스트 헬퍼.

## 3. 실행 흐름

### 사용자 요청 → 응답 사이클

```
1. 사용자 입력: "이 디렉토리의 파일 목록 보여줘"
       ↓
2. [cli] React UI가 입력 수신, core 전달
       ↓
3. [core] GeminiClient → LLM API 호출
   (providers/ 레이어가 Gemini/Claude/OpenAI 중 선택)
       ↓
4. LLM 응답: tool_call { name: "list_directory", args: { path: "." } }
       ↓
5. [core] 정책 엔진 → 사용자 승인 확인 (confirmation-bus)
       ↓
6. [core] ToolExecutor → 해당 도구 실행
   (shell, file, grep, glob, web-fetch, MCP 등)
       ↓
7. 도구 결과를 LLM에 다시 전달 → 다음 턴
       ↓
8. LLM 최종 텍스트 응답 생성
       ↓
9. [cli] 터미널에 마크다운 렌더링
```

### 도구 실행 상세

```
도구 요청 (LLM tool_call)
  ↓
ToolExecutor (core/scheduler/tool-executor.ts)
  ├── Shell Tool → ShellExecutionService
  │   ├── PTY 선택: node-pty > child_process
  │   ├── 셸 환경 설정 (bash/zsh/fish)
  │   └── 출력 스트리밍 (1초 간격)
  │
  ├── File Tools → read/write/edit 도구
  │   └── 로컬 파일 시스템 직접 접근
  │
  ├── Grep/Glob → ripgrep, glob 패키지
  │
  ├── Web Fetch/Search → HTTP 요청
  │
  └── MCP Tools → 외부 MCP 서버 호출
```

## 4. 샌드박스 시스템

### 왜 필요한가?

LLM이 도구를 통해 파일 삭제, 네트워크 접근 등 위험한 작업을 수행할 수 있음.
샌드박스는 **CLI 프로세스 전체를 격리된 환경에서 실행**하여 호스트 시스템을
보호.

### 작동 원리

```
[샌드박스 없이]
사용자 → CLI → LLM → 도구 → 호스트 OS에서 직접 실행 ⚠️

[샌드박스 있을 때]
사용자 → CLI 시작
  ↓
sandbox.ts: "샌드박스 설정이 있나?"
  ├── YES → CLI 프로세스를 컨테이너/Seatbelt 안에서 재실행
  │         컨테이너 내부: CLI → LLM → 도구 → 격리 환경 ✅
  └── NO  → 호스트에서 직접 실행
```

**핵심**: 도구별 격리가 아니라, CLI 프로세스 전체를 샌드박스 안에서 실행.

### 샌드박스 종류

| 방식     | 환경       | 설정 값        | 특징                                                 |
| -------- | ---------- | -------------- | ---------------------------------------------------- |
| Seatbelt | macOS 기본 | `sandbox-exec` | OS 네이티브, 가볍고 빠름. `.sb` 프로파일로 접근 제어 |
| Docker   | Linux, CI  | `docker`       | 컨테이너 기반, 완전 격리. Dockerfile로 이미지 빌드   |
| Podman   | Linux      | `podman`       | Docker 대안, rootless 컨테이너                       |
| 비활성   | 개발       | `false`        | 격리 없음                                            |

### 설정 우선순위

```
GEMINI_SANDBOX 환경변수
  ↓ (없으면)
~/.gemini/settings.json
  ↓ (없으면)
프로젝트 .env 파일
  ↓ (없으면)
기본값: macOS → Seatbelt, 기타 → 비활성
```

### Docker 샌드박스 상세

**Dockerfile**은 샌드박스 컨테이너 이미지를 정의:

```dockerfile
FROM node:20-slim
# git, python, ripgrep, jq 등 도구 설치
COPY didim-agent-cli-*.tgz      # CLI 패키지
COPY didim-agent-cli-core-*.tgz # Core 패키지
RUN npm install -g ...           # 글로벌 설치
CMD ["didim"]                    # 기본 엔트리포인트
```

**컨테이너 실행 시 마운트**:

```
호스트                         → 컨테이너
$(pwd) (작업 디렉토리)          → /path/inside/container
~/.gemini (설정)               → /home/node/.gemini
/tmp                           → /tmp
gcloud 설정 (있으면)            → /home/node/.config/gcloud
GOOGLE_APPLICATION_CREDENTIALS  → 동일 경로
```

**빌드 명령**: `npm run build:sandbox` → `scripts/build_sandbox.js` →
`docker build`

## 5. Build vs Bundle

| 명령                    | 용도     | 도구                      | 결과물                               |
| ----------------------- | -------- | ------------------------- | ------------------------------------ |
| `npm run build`         | 개발     | tsc (TypeScript 컴파일러) | `packages/*/dist/` (개별 .js 파일)   |
| `npm run bundle`        | 배포     | esbuild (번들러)          | `bundle/gemini.js` (~24MB 단일 파일) |
| `npm run build:sandbox` | 샌드박스 | docker/podman build       | 컨테이너 이미지                      |

### Bundle 상세

esbuild가 모든 패키지를 하나의 실행 파일로 번들:

```
esbuild.config.js
  ├── CLI Config:
  │   Entry: packages/cli/index.ts
  │   Output: bundle/gemini.js (~24MB)
  │   External: node-pty, keytar (네이티브 모듈)
  │
  └── A2A Server Config:
      Entry: packages/a2a-server/src/http/server.ts
      Output: packages/a2a-server/dist/a2a-server.mjs
```

**배포 경로**:

```
npm run bundle
  → bundle/gemini.js 생성
  → npm publish
  → 사용자: npm install -g @didim/agent-cli
  → /usr/local/bin/didim → bundle/gemini.js
```

## 6. 멀티 LLM 프로바이더 구조

```
packages/core/src/providers/
├── index.ts              # 부트스트랩, 프로바이더 팩토리
├── providerTypes.ts      # 공통 타입 정의
├── baseAdapter.ts        # 어댑터 기본 클래스
├── gemini/               # Gemini 프로바이더
│   ├── geminiAdapter.ts
│   ├── geminiConverter.ts
│   └── geminiStreamHandler.ts
├── claude/               # Claude 프로바이더
│   ├── claudeAdapter.ts
│   ├── claudeConverter.ts
│   └── claudeStreamHandler.ts
├── openai/               # OpenAI 프로바이더
│   ├── openaiAdapter.ts
│   ├── openaiConverter.ts
│   └── openaiStreamHandler.ts
└── common/               # 공통 유틸 (에러, 이벤트, 스트림)
```

모델 이름으로 프로바이더 자동 선택:

- `gemini-*`, `auto`, `pro`, `flash` → Gemini
- `claude-*` → Claude (Anthropic)
- `gpt-*`, `o1-*`, `o3-*` → OpenAI

| `bundle/sandbox-macos-*.sb` | macOS Seatbelt 프로파일                      |
| `CLAUDE.md` / `GEMINI.md`   | AI 에이전트용 프로젝트 컨텍스트              |
