## 🔧 리뷰 수정 사항

### 이슈 1 (Medium): ModelConfigBridge provider-aware 키 미적용

- **위치**: `src/services/modelConfigBridge.ts:74,172`
- **문제**: `registerLlmConfig()`이 model-only 키를 사용하여, 동일 모델명을 다중
  provider에서 사용 시 설정이 덮어쓰여 라우팅/설정 불일치 위험
- **수정**: `provider:model` 복합 키 도입
  - `registerLlmConfig()`: `config.provider`로 `provider:name` 키 생성
  - `resolveNonGemini()`: `provider:model` → `model` 순서로 폴백 조회
- **회귀 테스트**:
  - `should isolate configs when same model name registered under different providers`
  - `should not return wrong provider config for provider mismatch`

### 이슈 2 (Medium): GeminiAdapter.generateContentStream() 에러 미정규화

- **위치**: `src/providers/gemini/adapter.ts:117-127`
- **문제**: 스트림 생성/순회 예외가 `handleError()` 없이 그대로 전파되어
  멀티프로바이더 공통 에러 처리 일관성 파괴
- **수정**: `streamGenerator()` 내부에 try-catch 추가, `handleError()`로
  `LlmError` 정규화
- **회귀 테스트**:
  - `should normalize stream creation errors to LlmError`
  - `should normalize stream iteration errors to LlmError`

### 이슈 3 (Low): MaxListenersExceededWarning — 시그널 핸들러 누수

- **위치**: `src/telemetry/sdk.ts:317,321`
- **문제**: `process.on('SIGTERM')`/`process.on('SIGINT')` 핸들러가
  `shutdownTelemetry()`에서 제거되지 않아 재초기화 시 누적
- **판정**: Phase 2 ETC 범위가 아닌 기존 프로젝트 코드 — Phase 3 핸드오프에 기록
- **조치**: `phase3_handoff.md`에 #12 항목으로 추가
