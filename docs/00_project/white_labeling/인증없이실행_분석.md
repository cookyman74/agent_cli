## 9. 코드 리뷰 — 사용자 관점 잠재 이슈 (유효)

> **이 섹션은 여전히 유효합니다.** 멀티프로바이더 설계 구현 시 아래 이슈를
> 체크리스트로 활용하세요.
>
> **리뷰 기준일**: 2026-02-14 **검증 방법**: 실제 소스 코드 기반 흐름 추적

### 9.1 인증 미완료 시 빈 화면 문제 (심각도: 높음)

**문제**: 인증 없이 `AuthState.Authenticated`로 진입하면, `GeminiClient`가
미초기화 상태 → 프롬프트 입력 시 런타임 에러 발생.

**근거 코드**:

- `AppContainer.tsx:571` — `config.getGeminiClient()?.isInitialized()` 체크
- `useAuth.ts:125-126` — `config.refreshAuth(authType)` 없이는 클라이언트 생성
  안됨

**멀티프로바이더 설계 적용 시**: Step 1에서 ESC를 누르거나, 프로바이더 선택 후
API Key 입력을 취소한 경우에도 동일 이슈 발생 가능.

**대응 방안**:

1. 인증 미완료 시 입력창을 비활성화하고 상단에 지속적 안내 배너 표시
2. `/help`, `/auth`, `/settings` 등 인증 불필요 명령만 허용
3. 일반 프롬프트 입력 시 "인증이 필요합니다" 안내 → `/auth` 다이얼로그로 유도

### 9.2 환경변수 휘발성 (심각도: 중간)

**문제**: `export ANTHROPIC_API_KEY=...`는 터미널 세션 종료 시 사라짐.

**사용자 경험**: "어제는 됐는데 오늘 안 된다"

**멀티프로바이더 설계 적용 시**: 키체인 저장을 기본으로 하므로 완화됨. 단,
환경변수 방식을 선택한 사용자에게는 영구 설정 안내 필요.

**대응 방안** (안내 문구에 포함 필요):

```text
# 영구 설정 방법:
echo 'export ANTHROPIC_API_KEY=your_key' >> ~/.zshrc  # macOS
echo 'export OPENAI_API_KEY=your_key' >> ~/.bashrc     # Linux

# 또는 앱 내에서 영구 저장 (권장):
didim → /auth login → 프로바이더 선택 → API Key 입력 → 키체인에 자동 저장
```

### 9.3 안내 화면 1회 표시 후 설정법 유실 (심각도: 중간)

**문제**: 프로바이더 선택 화면이 인증 완료 후 다시 표시되지 않음. 설정 방법을
잊은 사용자가 프로바이더 변경 방법을 모를 수 있음.

**대응 방안**:

1. 시작 배너 또는 팁 메시지에 `/auth login` 명령 항상 포함
2. `/auth status` 명령 추가 검토 (현재 프로바이더/인증 상태 표시)

### 9.4 샌드박스 모드 충돌 (심각도: 높음)

**문제**: `gemini.tsx:449-451`에서 `initialAuthFailed=true`이면 `FatalError`
throw → 앱 종료. 멀티프로바이더 설계에서도 프로바이더 선택 미완료 상태에서
샌드박스 진입 시 동일 문제.

**근거 코드**:

```typescript
// gemini.tsx:449-451
if (initialAuthFailed) {
  throw new FatalError(
    'Initial authentication failed...',
    ExitCodes.FATAL_AUTHENTICATION_ERROR,
  );
}
```

**대응 방안**: 프로바이더 선택 미완료 시 `initialAuthFailed`를 `false`로
유지하거나, 샌드박스 진입 전 분기에서 별도 처리.

### 9.5 `/auth` 명령은 이미 존재 (정보)

- `/auth` 또는 `/auth login` → 인증 다이얼로그 열림
- `/auth logout` → 로그아웃 + 자격 증명 삭제

멀티프로바이더 설계에서는 `/auth login` → Step 1(프로바이더 선택)부터 시작하도록
변경.
